
# Sheet: 工作表1
| 一级场景                                | 二级场景                            | 场景痛点                                                                              | 解决方案                                                                                                       |
|:------------------------------------|:--------------------------------|:----------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------|
| 企业Agent资产管理                         | 企业级 Skill 资产管理                  | 1. Skill 分散在不同 Agent Runtime、代码仓库和本地文件中，缺乏统一管理。 2. Agent 配置 Skill 依赖手工逐一挂载，复用效率低。 | 1. 建设统一 Skill 中心，支持 Skill 的创建、更新、删除等全生命周期管理。                                                               |
|                                     |                                 |                                                                                   | 2. 提供技能包抽象，对 Skill 进行组合封装，支撑不同 Agent 快速完成技能装配。                                                             |
| 使用新增的Harness组件进行高代码开发               | 基于统一 Skill 管理能力开发高代码程序          | Skill 资产与实际开发实现相互割裂，开发者需要频繁切换多个界面传输skill资产，导致修改、验证与沉淀链路冗长。                        | 打通 Skill 资产管理与开发态，快速集成技能到开发容器，降低高代码开发切换成本。                                                                 |
| nan                                 | 基于统一的 Sandbox as Tool 沙箱开发高代码程序 | 1. 高代码 Agent 开发依赖复杂运行环境，涉及代码执行、依赖安装和外部任务调用，缺乏隔离环境时容易出现环境污染与调试不稳定。                 | 基于 K8s 的 Agent Sandbox 管理体系，提供隔离、可控的开发与运行环境，统一承载代码执行、依赖管理与结果验证，提升开发安全性、稳定性与环境一致性。                          |
|                                     |                                 |  2. 本地沙箱隔离能力有限，且生命周期管理成本高。                                                        |                                                                                                            |
| 使用Agent Harness 托管平台进行agent业务流的部署开发 | 企业场景下 Agent 生产部署与资源管理           | 1. Agent Harness 类型、数量多，统一管理复杂。                                                   | 1. 提供开箱即用的全功能 Harness，并将各类 Harness 组件抽象为标准化 Agent 资源：                                                      |
|                                     |                                 | 2. Agent 资源执行过程中存在闲置浪费，带来较高计算成本。                                                  | - Blueprint 定义 Agent 静态配置与工具集                                                                              |
|                                     |                                 | 3. Agent 运行依赖工具与环境配置，分散管理负担重。                                                     | - Environment 定义执行环境策略与依赖管理                                                                                |
|                                     |                                 | 4. Agent 执行 Skill 代码时依赖包安装复杂，环境一致性难保障。                                            | - Session 提供沙箱化执行与访问观测能力                                                                                   |
|                                     |                                 |                                                                                   | - Vaults 提供凭证托管能力。                                                                                         |
|                                     |                                 |                                                                                   | 2. Session 依托 Sandbox 能力支持闲置挂起，降低资源消耗。                                                                     |
|                                     |                                 |                                                                                   | 3. Blueprint 提供统一的工具配置抽象，支持模板化复用。                                                                          |
|                                     |                                 |                                                                                   | 4. Environment 预定义运行依赖，Session 启动前按挂载配置完成依赖安装。                                                             |
| nan                                 | 开发在企业业务流中控制 Agent 生命周期          | 现有 Agent Harness 平台多以提供完整运行框架为主，难以对 Agent 生命周期及底层组件资源进行细粒度控制。                     | 提供面向 Agent 原子组件的精细化控制能力与 SDK，支持对 Blueprint、Session、Environment、Vaults 等资源进行独立管理，后续可进一步扩展至 File、Memory 等资源。 |
| nan                                 | Agent 权限控制                      | 1. 多人使用 Agent 时，难以在用户粒度进行权限隔离。                                                    | 1. 通过 Vaults 管理用户访问外部工具的凭证，并与用户 Session 绑定，实现多用户权限隔离。                                                      |
|                                     |                                 | 2. Agent 沙箱访问策略缺乏统一控制。                                                            | 2. 通过 Environment 定义 Session 级访问与执行策略。 包括可访问网络与可访问MCP工具定义。                                                 |
|                                     |                                 | 3. 多用户并发访问时，运行上下文存在逃逸与相互影响的风险。                                                    | 3. 通过 Session 提供会话级隔离能力，保障多用户运行环境独立。                                                                       |
|                                     |                                 | 4. agent进行风险操作时，期望提供人类审核机制                                                        | 4. 结合blueprint定义MCP工具访问策略，风险工具触发人类审批流程。                                                                    |
| nan                                 | Agent观测与运维                      | 开源harness 无法提供统一的观测入口                                                             | agent factory harness基座集成langfuse插件，可以在agentbase统一观测页面或者session详情查看agent trace                             |
| 通过自然语言搭建Agent harness工具链            | 自然语言生成 Skill                    | 1. Skill 从零建模成本高，对非深度技术用户不友好，能力构建门槛高。                                             | 1. Agent 工坊支持通过自然语言生成 Skill 草稿，将需求表达直接转化为能力定义，降低初始建模门槛。                                                    |
|                                     |                                 |  2. Skill 创建后仍需调试与修改，缺少安全、连续的验证环境。                                                |  2. Skill 创建后可直接创建 Session 进行测试，基于反馈持续迭代优化。Session提供调试WebUI，可以满足agent工作流闭环。                                |
| nan                                 | 自然语言生成Agent定义                   | 用户通常明确业务目标，但难以快速拆解出合理的 Agent 结构与能力组合。                                             | 1. 基于自然语言理解与自动生成能力，将业务目标映射为 Blueprint 结构，缩短从需求到模板的构建路径。                                                    |
|                                     |                                 |                                                                                   | 2. Blueprint 创建后可直接创建 Session 进行测试，基于反馈持续迭代优化。                                                             |
